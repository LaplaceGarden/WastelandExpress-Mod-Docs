# 游戏内物品查询窗口设计文档

日期：2026-05-28

## 背景

《废土快递》的 Mod 开发者和玩家经常需要查询物品 ID、名称、描述、重量、价格、标签、装备字段等信息。当前仓库已经提供 `docs/database` 下的静态 CSV 数据，但它们主要面向外部文档查阅，不适合玩家在游戏内边玩边查。

本设计定义一个游戏内 Lua Mod：在游戏内打开一个只读窗口，以表格形式查看物品信息。

## 目标

第一版目标是提供一个游戏内「物品图鉴 / 物品查询器」窗口，支持：

- 在游戏内打开独立查询窗口。
- 查看物品、食物、装备、配件四类物品信息。
- 按名称、ID、描述、标签进行搜索。
- 按物品分类筛选。
- 在简约模式和详细模式之间切换。
- 保持只读，不修改游戏数据、存档或玩家库存。

## 非目标

第一版不做以下功能：

- 不发放、删除或修改物品。
- 不修改物品属性、价格、重量或标签。
- 不展示人员、派系、Buff、城市、任务、地牢技能等非物品数据。
- 不做菜谱、配方、自有城市合成等合成数据查询。
- 不做配方反查。
- 不做收藏、标记常用、历史记录。
- 不做 CSV 导出或联网更新。

## 数据范围

物品查询范围限定为四类数据：

- `物品.csv`
- `食物.csv`
- `装备.csv`
- `配件.csv`

这四类数据统一映射为内部记录 `ItemRecord`。不同来源没有的字段显示为空或 `-`。

## 数据模型

统一物品记录：

```text
ItemRecord
- id: number|string
- name: string
- sourceType: "物品" | "食物" | "装备" | "配件"
- level: number|string
- weight: number|string
- price: number|string
- iconId: number|string
- description: string
- tag: string
- characteristic: string
- buffId: string
- func: string
- funcPlus: string
- needSource: string
- attackRange: string
- rawFields: table
```

`rawFields` 保留原始字段，用于详细模式兜底展示，避免字段映射不完整导致信息丢失。

## 窗口入口

第一版推荐通过 Lua 函数或控制台命令打开窗口，例如：

```lua
ItemBrowser_Open()
```

选择这个入口的原因：

- 当前文档明确支持 Lua 脚本触发和 `OnGUI` 绘制。
- 对游戏原生 UI 注入依赖更少，第一版风险更低。
- 后续可以再扩展为主界面按钮、快捷键或已有菜单入口。

## 界面结构

窗口顶部固定显示：

- 标题：`物品图鉴`
- 搜索框：搜索名称、ID、描述、标签
- 分类筛选：`全部`、`物品`、`食物`、`装备`、`配件`
- 模式切换：`简约`、`详细`
- 关闭按钮

窗口默认打开简约模式。切换模式时保留当前搜索词、分类筛选和选中物品。

## 简约模式

简约模式用于边玩边查，是默认模式。

布局：

- 左侧是物品列表表格。
- 右侧是当前选中物品详情。

左侧表格列：

- `ID`
- `名称`
- `分类`

右侧详情字段：

- 名称
- ID
- 分类
- 等级
- 重量
- 价格
- 描述
- 标签
- 特性
- 类型专属字段摘要

类型专属字段摘要示例：

- 装备：`BuffID`、`Func`、`FuncPlus`、`AttackRange`
- 配件：`BuffID`、`Func`、`NeedSource`
- 食物：`Characteristic`、`Tag`
- 物品：`Characteristic`、`Tag`

## 详细模式

详细模式用于完整查表和字段对比。

布局：

- 窗口主体切换为宽表格。
- 搜索和分类筛选仍位于顶部。
- 表格支持纵向滚动；如果实现条件允许，支持横向滚动。

建议列：

- `ID`
- `名称`
- `内部名 / 英文名`
- `分类`
- `等级`
- `重量`
- `价格`
- `图标ID`
- `描述`
- `标签`
- `特性`
- `BuffID`
- `Func`
- `FuncPlus`
- `NeedSource`
- `AttackRange`

第一版默认按 ID 升序排序。点击表头排序作为后续增强，不纳入第一版必需功能。

## 搜索与筛选

搜索输入匹配以下字段：

- ID
- 名称
- 描述
- 标签
- 特性
- 内部名 / 英文名

匹配规则：

- 输入纯数字时，优先按 ID 精确匹配，同时保留模糊匹配能力。
- 输入中文或英文文本时，对上述字段做不区分大小写的包含匹配。
- 分类筛选与搜索条件同时生效。

性能策略：

- 如果即时搜索在游戏内 GUI 中性能稳定，则输入时实时过滤。
- 如果实时过滤有卡顿，则改为点击搜索按钮后过滤。

## 状态管理

窗口状态包含：

- 是否显示窗口。
- 当前模式：简约或详细。
- 当前搜索词。
- 当前分类筛选。
- 当前选中的物品 ID。
- 当前滚动位置。

切换模式时必须保留：

- 搜索词。
- 分类筛选。
- 选中物品。

关闭窗口时第一版可以不持久化状态。后续版本如果需要记住模式和搜索条件，再使用固有函数 `Save` / `Load` 保存 Mod 自己的数据。

## 数据来源策略

第一版优先使用静态数据随 Mod 分发。原因是当前仓库已包含 CSV 参考数据，但游戏内 Lua 是否能稳定读取外部 CSV 仍需验证。

实现前需要验证两种数据加载方式：

1. Lua 在 Mod 目录中读取 CSV 或文本数据。
2. 将四张 CSV 预处理成 Lua table，随 `main.lua` 或独立 Lua 数据文件分发。

如果方式 1 不稳定，采用方式 2。方式 2 的可控性更高，也避免运行时解析 CSV 的编码和转义问题。

## 错误处理

应处理以下情况：

- 数据文件缺失：窗口显示“物品数据未加载”，不报错刷屏。
- 某条记录字段缺失：该字段显示 `-`。
- 搜索无结果：显示空状态“没有找到匹配物品”。
- 选中物品不存在：自动清除选中状态或选中第一条结果。
- 数据解析失败：在控制台输出一次错误摘要，不在每帧重复输出。

## 视觉与交互原则

- 窗口应是工具型 UI，不做装饰性设计。
- 信息密度优先，但默认模式不能遮挡过多游戏画面。
- 表格字体使用可读的小字号，行高稳定。
- 按钮文案短：`全部`、`物品`、`食物`、`装备`、`配件`、`简约`、`详细`、`关闭`。
- 搜索框占主要宽度，方便快速输入。
- 详细模式可以更宽，但仍应允许一键回到简约模式。

## 验收标准

第一版完成后应满足：

- 可以在游戏内打开和关闭物品查询窗口。
- 默认进入简约模式。
- 可以切换到详细模式，并切回简约模式。
- 可以看到 `物品`、`食物`、`装备`、`配件` 四类数据。
- 搜索名称、ID、标签时能过滤结果。
- 分类筛选能正确过滤结果。
- 简约模式选中行后能显示详情。
- 详细模式能展示完整字段表格。
- 功能只读，不修改玩家库存、存档或游戏数据。
- 数据缺失或无搜索结果时不会导致 Lua 报错刷屏。

## 技术风险

主要风险：

- 游戏内 Lua 读取外部 CSV 的能力不确定。
- CSV 编码不统一，运行时解析可能遇到中文乱码。
- `OnGUI` 每帧绘制，如果搜索和表格渲染不做缓存，可能影响性能。
- 宽表格在 Unity IMGUI 中的滚动和列宽控制需要验证。

缓解措施：

- 第一版优先考虑把 CSV 预处理成 Lua table，减少运行时解析。
- 搜索结果缓存，只在搜索词、分类或数据变化时重新计算。
- 详细模式只渲染可视范围或限制单页行数，避免每帧绘制全部记录。
- 出错日志只输出一次，避免 `OnGUI` 或 `Update` 中反复 `print`。

## 后续扩展

后续可以考虑：

- 表头点击排序。
- 配方和菜谱关联查询。
- 物品来源说明。
- 记住上次打开模式。
- 快捷键打开窗口。
- 从已有游戏 UI 添加按钮入口。
- 收藏常用物品。
